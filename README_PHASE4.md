# Phase 4 — 投稿解析結果をSQLiteへ反映

## できること

Streamlit画面にスタダ便の完売ポスト本文を貼り付けると、

```text
投稿本文
↓
parser.py
↓
対象公演 / 商品 / variant を解析
↓
解析結果を画面で確認
↓
「反映」ボタン
↓
SQLiteの該当商品をSOLD_OUTに更新
```

まで実行できます。

## 重要

このPhaseではまだX APIへ接続しません。

自動更新前に人間が解析結果を確認できるため、
誤判定がないか検証するための段階です。

## 起動

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 確認手順

1. 完売ポスト本文を貼る
2. 「解析する」
3. 公演・商品・variantが正しいか確認
4. 「上記の解析結果を確認しました」にチェック
5. 「解析結果をSOLD_OUTとして反映」
6. 対象公演を開いて完売状態になったことを確認

## 元ポストURL

任意でXの元ポストURLを入力できます。

反映時に `source_post_url` としてSQLiteへ保存されます。

## 安全設計

以下の場合はSQLiteを更新しません。

- parserが対象外と判定
- 商品が一意に決まらない
- variantが一意に決まらない
- 公演を特定できない
- ユーザーが確認チェックを入れていない

## テスト

```bash
pytest -q
```

parser単体テストに加えて、

```text
投稿解析 → SQLite更新
```

の結合テストも追加しています。

## 次フェーズ

この手動貼り付け方式で誤判定がないことを確認したら、
X APIから新着投稿を取得して同じ処理へ流します。
