# Phase 3 — スタダ便完売ポスト解析

## 目的

X APIへ接続する前に、実際のスタダ便ポスト本文から以下を抽出します。

- 対象ツアー
- 公演日 / `sales_session_id`
- 商品
- variant（メンバー・サイズ）
- `SOLD_OUT` 状態

## 対応済みの投稿形式

- `・トレカケース（千田）`
- `・うちわ（竹野）`
- `・Tシャツ（M）`
- `・ICEx FRESHest!! アクリルスタンド` + `種類：竹野世梛`
- `・ICEx FRESHest!! Tシャツ` + `サイズ：M`
- `・ペンライト`
- 1投稿内の複数商品
- 会場 + Day1 / Day2 からの公演特定
- `8/22(土)` のような明示日付からの公演特定

## 安全側の挙動

以下は自動更新対象にしません。

- `【完売情報】` がない
- `本日分完売` がない
- 対象ツアーを特定できない
- 公演を特定できない
- 商品を特定できない
- variantが必要なのに指定がない
- variantを特定できない

誤更新するより「解析失敗」として止める方針です。

# item_aliases.csv による商品別名管理

商品名の略称・表記揺れは `parser.py` に直書きせず、
`data/item_aliases.csv` で管理します。

列：

```csv
alias,item_id,notes
```

例：

```csv
ペンラ,icex_penlight_ver4,略称
アクスタ,freshest_acrylic_stand,略称
生写真セット,photo_set_vol30,vol番号なしでは曖昧
生写真セット,photo_set_vol31,vol番号なしでは曖昧
生写真セット vol.30,photo_set_vol30,vol指定あり
```

## 同じaliasを複数行に登録できる理由

`生写真セット` のように1つの表記だけでは商品を一意に決められない場合、
同じaliasを複数の商品へ登録します。

この場合parserは勝手にどちらかを選ばず、

```text
商品表記が曖昧で複数候補があります
```

として自動更新を停止します。

一方、

```text
生写真セット vol.30
```

のように一意に決まるaliasなら自動解析できます。

## 商品マッチ順

```text
1. 公式商品名またはaliasの正規化完全一致
2. 一意に決まる部分一致・末尾一致
3. 複数候補なら解析停止
4. 候補なしなら解析停止
```

誤った在庫更新よりも、安全側に止める方針です。

## alias追加方法

スタダ便で新しい略称を見つけた場合、Pythonコードを変更せず、
`item_aliases.csv` に行を追加します。

例：

```csv
ペンラ,icex_penlight_ver4,略称
```

追加後は必ず、

```bash
pytest -q
```

を実行してください。
